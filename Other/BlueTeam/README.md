## Engineering expectations

Blue Team projects are expected to document:

- the problem being solved;
- architecture and trust boundaries;
- current behavior versus planned capability;
- validation entry points;
- limitations and threat assumptions;
- evidence that supports public claims;
- publication/OPSEC boundaries.

A successful build or validator run proves only the behavior that was tested. It does not automatically imply production readiness.

## Public / local boundary

Public Git contains the material needed to review the engineering work. Identity-bearing academic exports, raw environment captures, credentials, local-only configuration, and other unnecessary operational artifacts remain outside public Git history.

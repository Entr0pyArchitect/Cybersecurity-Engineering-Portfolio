`Other/` contains larger applied-learning projects that sit outside the numbered Project MadHatter core sequence.

The numbered projects focus on building individual engineering competencies. The Applied Learning track is where those competencies are combined into broader systems, capstones, and later-stage security research.

## Tracks

| Track | Focus | Current public state |
|---|---|---|
| [Blue Team](BlueTeam/) | Defensive engineering, secure systems, validation, and integrated applied projects | Active public project set |
| [Red Team](RedTeam/) | Authorized offensive-security research and future custom testing frameworks | Public planning/documentation only |

## Publication standard

Applied projects follow the same rules as the core portfolio:

- evidence before claims;
- explicit current-versus-planned capability;
- synthetic data where practical;
- no real credentials, private keys, live target data, or unrelated personal information;
- no raw operational material merely because it exists locally;
- offensive work requires an isolated lab, CTF, owned system, or explicit authorization;
- every public artifact is reviewed for scope, safety, cleanup, and OPSEC.

## Relationship to the core portfolio

The Applied Learning track is **not** a replacement for Projects 01-17. It is the later-stage integration layer used to apply concepts after the underlying engineering areas are understood and validated.
